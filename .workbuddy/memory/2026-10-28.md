## Vclip 数据库从 MySQL 迁移到本地 SQLite

**背景**：Vclip 原先用公司 MySQL（192.168.171.226:3306，借用的库名 `supabase`）存剪贴板数据。私人项目不想继续占用公司资源，改为本地 SQLite，从空库开始。

**架构澄清**：项目实际是 React SPA + `server.mjs`（Node 原生 `node:http`，无框架）双进程结构，不是纯前端。前端走 `fetch('/api/clips')`，`server.mjs` 负责静态托管 `dist/` + API + Basic Auth + 访问日志。`@supabase/supabase-js` 是早期死依赖（库名叫 supabase 容易看混）。

**方案选择**：用 Node 22 内置 `node:sqlite`（`DatabaseSync`），不用 better-sqlite3。理由：零第三方依赖、无需原生编译、单机私人场景够用；代价是 experimental 警告，已用 `--disable-warning=ExperimentalWarning` 抑制。服务端现在零 npm 依赖。

**关键实现点**：
- 数据库文件 `data/vclip.db`，首次启动自动建表；WAL + `busy_timeout=5000`
- 时间字段统一存 ISO8601 UTC（`strftime('%Y-%m-%dT%H:%M:%fZ','now')`）。SQLite 字典序比较等价于时间比较，前端 `new Date()` 解析正常
- `INSERT ... RETURNING` 一次拿回整行，替代 MySQL 的 `insertId` + 二次 SELECT
- 补回 `expires_at > now` 过滤（MySQL 版本丢了该条件，过期内容一直显示）
- 启动时 + 每 10 分钟 purge 过期记录；SIGINT/SIGTERM 优雅关闭
- `vite.config.ts` 增加 `/api` → `localhost:4173` 代理，修复 `npm run dev` 下接口 404

**验证**：接口增删查、401 鉴权、过期过滤、purge、静态资源、`npm run build` 全部实测通过。

## 修复入口路径校验 + Windows 一键启动

**secret path 安全加固**：原先校验只在前端（`currentPath !== secretPath`），而 `VITE_SECRET_PATH` 会被编译进 bundle，看源码即得入口。改为服务端校验：
- `server.mjs` 新增 `matchesSecretPath()`，仅对页面请求校验（`/assets/*` 放行），不匹配返回真正的 HTTP 404 + 独立 HTML，不再吐 `index.html`
- `App.tsx` 删掉前端校验，入口字符串彻底从前端产物消失（grep 验证 bundle 中出现 0 次）
- 环境变量改名 `SECRET_PATH`（服务端专用，无 `VITE_` 前缀），保留对 `VITE_SECRET_PATH` 的兼容读取

**启动vclip.bat 无法运行的真实原因**：这台机器没有系统级 Node.js —— USER/MACHINE PATH 均无 node，`C:\Program Files\nodejs` 不存在。之前 `where npm` 能返回，是因为 WorkBuddy 进程给 shell 注入了 `C:\Users\Administrator\.workbuddy\binaries\node\versions\22.22.2-6`。双击 bat 时 Explorer 用的是持久化环境变量，找不到 npm。

修复：bat 内先 `where node`，失败则扫描 `%USERPROFILE%\.workbuddy\binaries\node\versions\*` 注入 PATH；另补 `cd /d "%~dp0"`、缺 node_modules 自动 `npm install`、缺 dist 自动 build、失败 pause。文件转 CRLF + ASCII 避免乱码。

**验证**：清空 PATH 至仅 `C:\Windows\System32` 后运行 bat，成功启动并输出 `v22.22.2`；路由测试 `/`→404、正确入口→200、`/wrong`→404、`/assets/*.js`→200、`/api/clips`→200、无凭据→401。
