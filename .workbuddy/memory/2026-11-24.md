## 18:20 缩略图评估 + 修拖拽出口
用户报「从 Vclip 往出拖图片，拖出来的是缩略图」。核实属实：列表 `<img src>` 就是缩略图，浏览器原生拖拽拖的就是 src。

**实测（局域网 IP 直连，各 5 次）**：692KB 原图 3.3~4.6ms，10KB 缩略图 2.2~2.7ms → **带宽优势只剩 1~2ms，隧道停掉后基本归零**。
缩略图现在唯一价值是解码内存：3840×2160 解码位图 ≈33MB，480×270 ≈0.5MB（63×）。手机/VR 一屏十几张才顶得住。

**用户选了 B：保留缩略图 + 修拖拽出口**（拖拽目标=资源管理器，Chrome 自带下载器会带 Cookie，可行）。

改动（`src/App.tsx`，其余未动）：
- `onImageDragStart()`：`dataTransfer.setData('DownloadURL', 'mime:filename:url')` + `text/uri-list`，均指向原图；
  pending / blob 阶段直接 `preventDefault`（还没落地）
- `mimeFromName()` 按扩展名映射 MIME，服务端只收 png/jpg/jpeg/gif/webp
- `brokenThumbs: Set<number>` 状态：缩略图 onError 时退回原图（**派生数据不能当唯一真相**，
  原图完好却看不见是结构性风险）；原图也挂才显示「图片加载失败」
- README 补了两段：拖拽拿到的是原图、缩略图丢失会回退

**验证（CDP 合成 DragEvent + 真图记录）**：
- `displayed` = `...-t.png`，`DownloadURL` = `image/jpeg:<原图名>:http://.../api/media/<原图名>` ✅
- 删掉缩略图文件后重载：`src` 自动切到原图，`naturalWidth=3840` ✅
- 测试条目与 `.probe` 目录已清理

**经验**：要验「拖出去是什么」，用 `new DataTransfer()` + `new DragEvent('dragstart')` 派发到 img 上再读
`dt.getData('DownloadURL')` 就行，不需要真的跨应用拖；跨应用拖在无头环境里没法验。
