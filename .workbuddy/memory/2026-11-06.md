### 1. 图标重绘（V 从 69.5% 收到 57%）
- `public/icon.svg`：path 改为 `M110 110 L180 110 L256 292 L332 110 L345 110 L402 167 L291 402 L221 402 Z`
  （原 `M78 78 ... 434`，四周留白 78 → 110）
- 新增 `public/icon-maskable.svg`：V 收到 52%，上尖距圆心 186 < 204.8（80% 安全圆半径）
- 重出 4 张 PNG：icon-512 / icon-192 / apple-touch-icon(180) / icon-maskable-512
  - 用 Edge `--headless=new --screenshot` + `--force-device-scale-factor=0.3515625`(→180) / `0.375`(→192)
  - **小尺寸不能直接 `--window-size=180,180`**：渲染出来只有背景没有 V（截图早于绘制）。窗口固定 512 再改 scale factor 才对
  - **`<img src="x.svg">` 会截空**，必须把 SVG 内联进 HTML

### 2. 域名下图标不生效 = 三个叠加原因（都不是图标本身坏了）
1. **Cloudflare 边缘缓存旧图**：旧响应没有 `Cache-Control`，CF 自动打 `max-age=14400`，
   `cf-cache-status: HIT` + `Age: 1204`，服务器换了图边缘还在喂旧的
2. **登录页没有 apple-touch-icon 声明**：公网未登录时所有页面 302 到 `/__login`，
   在登录页点「添加到主屏幕」→ iOS 抓不到图标 → 灰方块
3. iOS 系统级图标缓存：已添加到主屏的 PWA 必须删掉重加
- 修法：图标 URL 全部加版本号（index.html 手写 `?v=2`，manifest 用 mtime 36 进制自动生成）
- 我也一度测错域名：根域名 `qqtang-match.fun` 是 1033，实际映射的是 **`dora.qqtang-match.fun`**

### 3. 静态资源传输层重写（server.mjs）
之前每个文件都是 `writeHead(200,{Content-Type})` + `createReadStream` 裸流，等于：无压缩、无 Cache-Control、无 ETag、无 Content-Length（chunked）。
- 新增 `loadStaticAsset()`：br(q5)/gzip(6) 压缩一次进内存 Map 缓存，key = path+mtime+encoding
- `cacheControlFor()`：`/assets/` → `max-age=31536000, immutable`；html/webmanifest → `no-cache`；图标 → `max-age=604800`
- 支持 `If-None-Match` / `If-Modified-Since` → 304
- `sendJSON` 加 `Cache-Control: no-store`（剪贴板内容是隐私，不许 CF 缓存）
- `server.keepAliveTimeout = 65_000` / `headersTimeout = 66_000`（默认 5s，隧道复用连接会撞 ECONNRESET）
- 效果：JS **340KB → 103.9KB**（-69%），gzip 108.9KB

### 4. 隧道实况（重要）
- 服务是 **remote-managed**：`cloudflared tunnel run --token-file C:\ProgramData\cloudflared\token`
  → 所以 `~/.cloudflared/config.yml`（里面写的是 `qqtang-match.fun → localhost:3000`）**完全不生效**，路由在 Dashboard
- Dashboard ingress：`dora.qqtang-match.fun → http://localhost:4173`（端口是对的）
- 诊断：`cloudflared tunnel run --token-file ...` 前台跑一次能看到 ingress 配置 + connectivity pre-check + `Registered tunnel connection ... location=lax13`
- **慢的真相**：回源落在 **LAX（洛杉矶）**；且实测
  - 走系统代理(127.0.0.1:11420)：ttfb 1.7~9.1s，total 2.3~11.8s
  - 直连（--noproxy）：ttfb 1.7~15.6s，**total 全部 30s 超时**（响应体传不完）→ 这就是「有时候加载不出来」

### 待办

- CF 那边旧的 `/icon-192.png`（无 query）还在缓存，4h 后自然过期，或手动 Purge

## 追加：域名下「添加到主屏幕」图标退化成简陋 V（同日 09:30）

### 现象
内网 PWA 图标正常，域名添加主屏变成「简陋的纯色 V」；浏览器 tab 的 favicon 反而是对的。

### 根因（有实测数据）
1. `apple-touch-icon.png`（180，25.7KB）在隧道下**传不完**：
   连续 4 次请求，3 次在 **18~24KB 处卡死**，20s 超时（`code=200` 但 body 没到齐）
2. iOS 抓图标有超时限制 → 拿不到 → **退回 `<link rel="icon" type="image/svg+xml">`**
3. iOS 的 SVG 渲染器不支持 `feDropShadow` / 复杂渐变 → 只剩一个纯白 V + 纯色底
   = 用户看到的「简陋的 V」
4. 内网是局域网直连无带宽瓶颈，25KB 秒到，所以内网一直正常

### 修法：把图标压到几 KB + 换全新文件名
- 纯双色版（背景 `#0F0D1F` + 纯白 V，去渐变/光晕/投影）实测体积：
  | 版本 | 180px | 512px |
  |---|---|---|
  | 纯双色 | **3.1KB** | **9.5KB** |
  | 背景渐变+白V | 14.5KB | 82.7KB |
  | 原版(渐变+光晕+投影) | 25.7KB | 172KB |
  → 180px 上肉眼区分不出，体积差 8 倍，只能选纯双色
- 新文件名 `apple-touch-icon-180.png`（不带 query）：iOS 与 CF 都按完整 URL 缓存图片，
  **换文件名是唯一能可靠绕开双层缓存的写法**
- `icon.svg?v=3` / `icon-192.png?v=3` 给桌面浏览器
- CF 已预热成 `cf-cache-status: HIT` / `Age: 93`，手机端直接吃边缘缓存

### 结论
- 链路本质问题是家庭宽带上行 + CF 回源 LAX，**3KB 仍偶发失败**（5 次里 2 次超时），
  但比 25KB 的几乎必失败好太多
- 添加主屏时如果还是灰图标，**多试一两次**，或先打开页面预热再添加

## 追加：图片传输能力实测（同日 14:00，用户问「2MB 图能不能快速加载」）

### 关键结论：不是「慢」，是「基本传不完」；瓶颈在**家宽上行**，不是下行

| 环节 | 实测 | 备注 |
|---|---|---|
| 局域网读 1.52MB | 9ms / 165 MB/s | `curl` 到 127.0.0.1:4173 |
| 本机 → CF 边缘 **上传** | **112 KB/s**（1.52MB 用 13.9s） | `POST speed.cloudflare.com/__up`；第 2 次直接失败 |
| CF 边缘 → 本机 **下载** | **850 KB/s**（2MB 用 2.3s） | `speed.cloudflare.com/__down`，说明下行不缺 |
| 走隧道读 1.52MB | 40s 只收到 0~1.1MB，**从未传完** | 多次重试 |
| 走隧道读 100KB | 4 次里 3 次卡死；成功那次 **17.5 KB/s** | |
| 走隧道读 3.1KB 图标 | 5 次里 2 次失败 | |

→ 回源方向 = 家宽**上行**，理论 112KB/s，隧道实际只有 **~25KB/s**。
→ 2MB 一张：理论 ≥18s，实际 80s+ 且大概率中途断；3 张 = 几分钟。

### 顺手排除的两个误判
- **隧道协议不是主因**：临时起一个 `--protocol http2` 连接器并测，仍只有 ~25KB/s
  （CF 自己的 precheck 确实 `suggested_protocol=http2`，说明 QUIC 路径有丢包，但换协议救不回来）
- **cookie 认证没问题**：本地用 `LAN_FREE_ACCESS` 拿到的 200 不代表 cookie 对；
  必须用 `POST /__login` 真实 Set-Cookie 再测，否则会误判成「域名下 401」
- `logAccess()` 有 `if (!isPageRequest(urlPath)) return;`，**带扩展名的 `/api/media/*.jpg` 不写日志**，
  别拿「日志没有记录」当「请求没到」

### 当前代码的图片策略（对有损问题很关键）
- `src/App.tsx`：`COMPRESS_THRESHOLD=900KB`、`MAX_EDGE=2400`、`toBlob('image/jpeg', 0.86)`
  → **>900KB 的图会被 canvas 重编码，不是无损**；≤900KB 才原样直传
- `server.mjs`：`MAX_IMAGE_BYTES=8MB`，只做魔数嗅探后原样落盘，`private, max-age=31536000, immutable`
- 列表渲染 `src={mediaUrl(clip)}` → **直接加载原图**，N 张 2MB 就是 N×2MB 流量

### 待用户决策的方向
- A. 原图无损落盘 + 上传时生成 480px 缩略图，列表只加载缩略图（约 40KB/张）
- B. 换传输通道：EasyTier 虚拟网 10.126.126.3:4173 直连（已装），或 Tailscale 组网 → 接近局域网速度
- C. 不动，仅在 UI 上明确「原图加载中」

## 落地：原图无损 + 缩略图（用户选 A，B 的通道他已自行掌握）

### 服务端 `server.mjs`
- 启动时 `PRAGMA table_info(clips)` 检测，缺列则 `ALTER TABLE clips ADD COLUMN thumb TEXT`
- 所有 SELECT/RETURNING 补上 `thumb`；`getById` 也带上（删除时要一起清）
- 新增 `POST /api/clips/:id/thumb`：接原始二进制，`MAX_THUMB_BYTES = 512KB`，
  **同样走魔数嗅探**（不能只信前端），落盘名 `${Date.now().toString(36)}-${uuid}-t.${kind}`
  重传时删旧缩略图；clip 不是 image 或不存在 → 404
- `purgeExpiredClips` / `pruneOrphanUploads` / DELETE 三处都改成同时处理 `content` + `thumb`

### 前端 `src/App.tsx`
- 删掉 `COMPRESS_THRESHOLD/MAX_EDGE/shrinkImage`（有损重编码）
- `NATIVE_IMAGE_TYPES` 命中 → **原样上传**；未命中（HEIC/TIFF/BMP）才 `transcodeToJpeg` q0.92
- `makeThumbnail()`：长边 480，WebP q0.72，不支持 WebP 时退回 JPEG 0.8 + 深色底
- 上传后串行补传缩略图，失败静默（列表退化到原图）
