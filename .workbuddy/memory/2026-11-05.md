## 临时开公网映射（公网:50777 → 192.168.171.4:4173）的可行性结论

**结论：能进，但会要密码。** 公网来源 IP 不在私有网段 → `isLanTrusted()` 为 false → 走登录页；输对密码后 302 回 `/<SECRET_PATH>` 并下发 365 天 Cookie。

**模拟实测**（4199 实例 + `LAN_FREE_ACCESS=false`，等价于公网来源）：
- `/<SECRET_PATH>` 未登录 → 302 `/__login?next=%2F<SECRET_PATH>`
- 错密码 → 302 `/__login?error=1&next=%2F<SECRET_PATH>`；对密码 → 302 `/<SECRET_PATH>` + Set-Cookie
- 带 Cookie：`/<SECRET_PATH>` → 200、`/` → 404、`/api/clips` → 200、`manifest.webmanifest` → 200 且 `start_url=/<SECRET_PATH>`

**环境事实**：
- 4173 **当时无监听**，测之前必须先 `启动vclip.bat`
- 防火墙 `Allow EasyTier TCP 4173` 已是 Inbound / Allow / Any profile / RemoteAddress=Any → 端口映射后无需再加规则
- 出口 IP `221.11.22.70`（联通 西安），不属 CGNAT `100.64/10` → 具备映射条件；仍需确认路由器 WAN 口 IP 与之一致

**唯一会打穿密码层的坑（必须实测确认）**：部分路由器对转发流量做 SNAT，服务端看到的来源变成路由器内网 IP（如 192.168.171.1）→ 命中 `isPrivateAddress()` → `lanBypass` 成立 → `/<SECRET_PATH>` 免密直进，且 `/` 照旧 404，表现上完全看不出问题。
判据：外部设备访问后看 `logs/access-YYYY-MM-DD.log` 第一列。是公网 IP → 正常；是 `192.168.x.x` / `10.x` → 已被 SNAT，应临时把 `.env` 改 `LAN_FREE_ACCESS=false` 并重启（已有 Cookie 的设备不受影响）。

**真正的风险不在路径而在口令**：`/__login` 无失败限速，6 位数字口令在公网可被脚本爆破；且公开仓库历史 `162d88c` 已含真实入口路径，原先"知道也进不去"的前提在开公网后不再成立。两天窗口内最低成本的两条：临时轮换 `SECRET_PATH`，或给 `/__login` 加按 IP 失败计数。

## 改用 Cloudflare Tunnel 代替端口映射 —— 补丁已打

**用户决定**：不开公网端口映射，走 cloudflared 隧道；**不改 `LAN_FREE_ACCESS`**；要求局域网继续免密、隧道访客输一次密码后靠 Cookie 免输。

**原代码在这条路上的致命组合**：cloudflared 与 Vclip 同机，从 `127.0.0.1` 连进来 → `isPrivateAddress('127.0.0.1')` 为 true → `lanBypass` 成立 → **整条隧道变成免密后门**：知道入口路径的人直进，`/api/*` 全开，而 `/` 照旧 404，表现上完全看不出来。实测（生产 `.env`，LAN=true）：回环来源无 Cookie 访问入口路径 → **200**。

**改法（`server.mjs`）**：
- 新增 `localAddresses`：回环 + 本机所有网卡地址，启动时快照（覆盖 `--url localhost` 与 `--url 192.168.171.4` 两种写法）
- `getClientIp()` 重写：对端**不在** `localAddresses` 时只返回 socket 地址，转发头一概不读（防伪造）；对端**是本机**时才依次采信 `CF-Connecting-IP` → `X-Forwarded-For` 首段 → socket
- `isLanTrusted()` 改用 `getClientIp()`；删掉不再使用的 `getSocketIp()`
- `logAccess` 顺带受益：日志记录的是隧道访客真实 IP（实测出现 `8.8.8.8`）

**实测矩阵（4199 实例，生产 `.env`，LAN=true）**：
回环无头 → 200（本机浏览器行为不变）；回环 + `CF=8.8.8.8` → 302 登录页；同场景 `/api/clips` → 401；仅 `XFF=8.8.8.8` → 302（兜底生效）；输密码 → 302 + Cookie 含 `Secure`（因带 `X-Forwarded-Proto: https`）；带 Cookie 再访问 → 200；带 Cookie 访问 `/` → 404；`CF` 头为 `192.168.171.112` → 200（私有地址视为可信，符合预期）；局域网 `192.168.171.4` 直连入口路径 → 200、`/api/clips` → 200。

**测试盲区（要记住）**：真实局域网设备伪造 `X-Forwarded-For` 无法在本机复现——本机发往自己网卡地址时 socket 也落在 `localAddresses` 里。防护依据是代码结构：非本机对端在读取任何头部**之前**就 `return socketIp`。

**文档同步**：README 判定规则表新增「同机反向代理 / 隧道」一行 + 说明段；`.env.example` 补一行；顺手把「只 import 四个内置模块」修正为实际的六个。

**环境事实**：本机尚未安装 cloudflared（`tasklist` 无进程）。隧道指向必须用 `--url http://localhost:4173`，不要指向 `192.168.171.4`（虽然本补丁也覆盖了，但 localhost 语义最清晰）。
