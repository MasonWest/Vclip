## 临时开公网映射（公网:50777 → 192.168.171.4:4173）的可行性结论

**结论：能进，但会要密码。** 公网来源 IP 不在私有网段 → `isLanTrusted()` 为 false → 走登录页；输对密码后 302 回 `/<SECRET_PATH>` 并下发 365 天 Cookie。

**模拟实测**（4199 实例 + `LAN_FREE_ACCESS=false`，等价于公网来源）：
- `/<SECRET_PATH>` 未登录 → 302 `/__login?next=%2F<SECRET_PATH>`
- 错密码 → 302 `/__login?error=1&next=%2F<SECRET_PATH>`；对密码 → 302 `/<SECRET_PATH>` + Set-Cookie
- 带 Cookie：`/<SECRET_PATH>` → 200、`/` → 404、`/api/clips` → 200、`manifest.webmanifest` → 200 且 `start_url=/<SECRET_PATH>`

**环境事实**：
- 4173 **当时无监听**，测之前必须先 `启动vclip.bat`
- 防火墙 `Allow EasyTier TCP 4173` 已是 Inbound / Allow / Any profile / RemoteAddress=Any → 端口映射后无需再加规则
- 出口 IP `221.11.22.70`（联通 西安），不属 CGNAT `100.64/10` → 具备映射条件；仍需确认路由器 WAN 口 IP 与之一致

**唯一会打穿密码层的坑（必须实测确认）**：部分路由器对转发流量做 SNAT，服务端看到的来源变成路由器内网 IP（如 192.168.171.1）→ 命中 `isPrivateAddress()` → `lanBypass` 成立 → `/<SECRET_PATH>` 免密直进，且 `/` 照旧 404，表现上完全看不出问题。
判据：外部设备访问后看 `logs/access-YYYY-MM-DD.log` 第一列。是公网 IP → 正常；是 `192.168.x.x` / `10.x` → 已被 SNAT，应临时把 `.env` 改 `LAN_FREE_ACCESS=false` 并重启（已有 Cookie 的设备不受影响）。

**真正的风险不在路径而在口令**：`/__login` 无失败限速，6 位数字口令在公网可被脚本爆破；且公开仓库历史 `162d88c` 已含真实入口路径，原先"知道也进不去"的前提在开公网后不再成立。两天窗口内最低成本的两条：临时轮换 `SECRET_PATH`，或给 `/__login` 加按 IP 失败计数。
